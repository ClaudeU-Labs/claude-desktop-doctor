# Contributing

Thank you for helping improve Claude Desktop Doctor.

## Before opening a change

1. Keep the tool read-only and offline by default.
2. Add the smallest check that answers a concrete Windows troubleshooting question.
3. Do not collect configuration contents, raw logs, process arguments, account data, network addresses, or secrets.
4. Add every new report field to the allowlist and JSON Schema.
5. Use synthetic fixtures only. Never commit official application assets or private user data.

## Development

The project supports Windows PowerShell 5.1 and PowerShell 7+ without third-party dependencies.

```powershell
powershell -NoProfile -File .\tests\run-tests.ps1
powershell -NoProfile -File .\tests\run-sensitive-scan.ps1
```

Run both commands before opening a pull request.

## Pull requests

A pull request should include:

- the user-visible problem being diagnosed;
- why existing checks are insufficient;
- the exact metadata read by the new check;
- report fields added or changed;
- privacy and offline-mode tests;
- a rollback plan if the change affects an existing report contract.

Do not include generated reports from a real workstation. Use synthetic examples constructed inside tests.

## Issues

Use the structured Issue Forms. A diagnostic report generated by this tool may be attached after manual review. Never attach raw logs or configuration files.
